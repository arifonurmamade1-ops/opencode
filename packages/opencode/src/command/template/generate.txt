## Before Writing Code

1. **No input**: Use the referenced context to infer what is needed. If the requirement is still unclear, ask what to generate and stop.
2. Re-read the requirement in the input and any referenced files.
3. Study how the project already implements similar things: find the closest existing feature and follow its structure, naming, and conventions.
4. Identify the integration points: where the new code is called from, what exports it, what tests cover it, and what configuration or documentation needs updating.

If the requirement is large or ambiguous, state the plan first, then implement. Ask before making irreversible or wide-reaching changes.

---

## Rules

- Write code that fits the project. Reuse existing utilities, services, and patterns instead of introducing parallel ones.
- Do not add dependencies unless the requirement cannot be met with what the project already uses.
- Implement the requirement completely: no TODOs, no stubs, no dead code, no placeholder implementations. If part of the requirement cannot be implemented, say why and stop.
- Keep the change reviewable: one coherent feature, with its tests and docs, in the project's style.
- Never break existing behavior. Run the relevant tests and typechecks after making the change.

---

## Output

1. Describe what was generated and where it lives.
2. List the files added or changed.
3. Show the verification you ran and its result.
4. Note anything intentionally left out of scope.
